Просьба владельца выкатить в этом разговоре — уже разрешение (CLAUDE.md, «Безопасность»). Не переспрашивать «деплоим?», не пересказывать план — сделать и доложить.

1. `git status --short` и `git log --oneline origin/main..HEAD`. Свои незакоммиченные правки — сначала закоммитить и запушить (явными путями, без `Co-Authored-By`). Чужие незакоммиченные — не трогать: деплой берёт рабочее дерево, поэтому назови их в отчёте; если они ломают проверку — остановись и скажи.
2. Проверка. Скрипт деплоя сам гоняет typecheck, biome и юнит-тесты, но не приёмку. Если в этом разговоре полная проверка (`check`, тесты, `acceptance`) уже была зелёной на текущем `HEAD` и после неё ничего не менялось — не повторять. Иначе: `docker compose up -d dev fakes` → `docker compose run --rm acceptance` (по одному, чужой прогон — подождать; после новой миграции или правки `wrangler.jsonc` — сначала `docker compose restart dev`). Красное — не деплоить, доложить падение.
3. Новые миграции с прошлого деплоя (`git log --oneline -- migrations` за последние коммиты) — после применения их не исправить; упомянуть в отчёте, но не спрашивать.
4. `docker compose run --rm deploy` (таймаут до 10 мин). `.env` не читать; строки с секретами из вывода не пересказывать — фильтровать: `| grep -vi "secret\|token\|key" | tail -25`.
5. Отчёт в 2–4 строки: версия (`Current Version ID`), цепочки LLM / STT / голос / фото из вывода, webhook установлен, что ушло (коммиты, миграции), что не проверено.
