---
description: Деплой в прод — только после явного «да» владельца в этом разговоре
---
Владелец просит деплой. Деплой меняет прод: миграции D1 `--remote`, код Worker'а, секреты, webhook Telegram.

1. Покажи, что уйдёт: `git status --short` и `git log --oneline origin/main..HEAD` (если origin есть). Незакоммиченное чужое — назови.
2. Прогони проверку как в `/check` (check, тесты, приёмочные). Красное — стоп, деплой не предлагай.
3. Новые миграции (`git diff --name-only origin/main -- migrations` или по истории) — перечисли: после применения их уже не исправить.
4. **Спроси явное подтверждение** («деплоим?») и жди ответа. Без «да» в этом разговоре — не запускать.
5. После «да»: `docker compose run --rm deploy`. `.env` не читать и не печатать; вывод секретов не пересказывать.
6. Доложи адрес Worker'а, цепочки LLM/STT из вывода и результат установки webhook. Предложи проверить `/admin` → «здоровье».
