# ADR-0005. Обработка входящих событий, синхронизация и разбор дат

- Статус: **принято** (2026-10-04). Хостинг — **Cloudflare Workers, TypeScript** (по расчёту [research/hosting-economics.md](../research/hosting-economics.md)); возможный будущий переезд на Go + VPS страхуется переносимыми тестами (ADR-0006).

## Решения

### 1. Inbox для апдейтов Telegram
- Webhook принимает апдейт, сохраняет его в inbox (дедупликация по `update_id`) и **сразу** отвечает 200.
- Обработка — асинхронно воркером из inbox: STT, LLM, Google API могут занимать 3–8 сек и больше.
- Повторная доставка Telegram не создаёт повторных действий (US-05).
- Inbox хранится ограниченное время `[допущение: 7 дней]` для отладки, без аудио.

### 2. Изменения в календаре — push, не опрос
- На каждый подключённый календарь — канал `events.watch` → HTTPS-webhook.
- Уведомление Google сообщает только «что-то изменилось» → инкрементальная синхронизация `events.list` по `syncToken` (хранится на календарь).
- **Одна подписка на календарь**, а не на пользователя: общий календарь дома, на который подписан каждый член семьи, иначе даст дубли. Собственные изменения бота (эхо) распознаются и отбрасываются.
- Каналы истекают → планировщик продлевает их заранее; при потере `syncToken` (410) — полная пересинхронизация окна `[допущение: −1 / +60 дней]`.
- По изменениям пересчитываются напоминания, поручения и эскалации (US-71, US-91).
- Страховка: редкая сверка по расписанию `[допущение: раз в сутки]` на случай пропущенных уведомлений.

### 3. Даты — детерминированный парсер
- LLM определяет интент, название и календарь. **Фрагменты дат и длительности код извлекает из исходного текста сам** (`src/dates/extract.ts`: самые длинные куски, которые разбирает парсер; незнакомое слово обрывает кусок). Фрагменты от LLM — только запасной вариант. Причина — замер в ADR-0002: модель теряет части дат.
- Абсолютные значения вычисляет только код по [date-rules.md](../date-rules.md).
- Парсер покрыт тестами на корпусе реальных фраз (ADR-0002) и правилах неоднозначности.
- Если парсер не смог разобрать фрагмент — не догадываемся, а уточняем у пользователя.

### 4. Планировщик
Единый `ScheduledJob` (ADR-0003) для дайджестов, напоминаний, эскалаций, продления push-каналов. Точность — до минуты.

### 5. Экономия на LLM
Расчёт ([research/hosting-economics.md](../research/hosting-economics.md)) показал, что AI на 1–2 порядка дороже хостинга. Поэтому: один вызов LLM на команду (а не 1.5), статическая часть промпта (схема интентов, правила) — кешируемый префикс, выбор модели — по бенчмарку ADR-0002 с учётом цены (Qwen3-30B / gpt-oss-20b против Llama 70B — разница в бюджете 5×).

### 6. Хранилище и очередь (решено 2026-10-04)
- **Хранилище — D1.** KV — только кеш, Durable Objects не используем, пока не понадобятся.
- **Inbox — Cloudflare Queues:** webhook кладёт апдейт в очередь и отвечает 200; consumer обрабатывает (до 15 мин на сообщение, повторы при ошибке). Дедупликация по `update_id` — в D1. Лимит Free — 10k операций/день (~3 на сообщение): хватает на автора и тестовых пользователей; к бете — Workers Paid.
- **Планировщик** — Cron Trigger раз в минуту + таблица `scheduled_jobs` в D1 с индексом по `fire_at`; задачи раздаются в ту же очередь, чтобы один вызов cron не упирался в лимиты subrequests.

### 7. Модели (решено 2026-10-04)
- В первом приближении — **самые дешёвые**: STT `@cf/openai/whisper-large-v3-turbo`, LLM `Qwen3-30B-A3B` на Workers AI (~$0.10 на активного пользователя в месяц, ~30 пользователей в бесплатной квоте).
- Бенчмарк (ADR-0002, набор 2 из ADR-0006) — только если качество окажется проблемой.
- Проверить при старте: поддержку function calling у выбранной модели на Workers AI.

### 8. Парсер дат (решено 2026-10-04, пересмотрено после замера)
- **Свой детерминированный парсер, без chrono-node.** Замер chrono на золотом корпусе — 40%, и главное: уверенно-неверные ответы на русском («в пять минут восьмого» → 10:05, «через полтора часа» → 11:00, «в 12 ночи» → полдень), см. [research/date-parser-baseline.md](../research/date-parser-baseline.md).
- Устройство (`src/dates/`): токенизатор с числительными словами → грамматика (момент, период, сдвиг, длительность, повторение) → правила date-rules.md. Любое незнакомое слово → `unparseable`.
- Одна грамматика — одинаковое поведение при переносе на Go; золотой корпус (`testdata/dates/`, ADR-0006) — спецификация и регрессия (`npm test`).
