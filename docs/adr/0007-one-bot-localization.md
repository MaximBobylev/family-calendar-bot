# ADR-0007: Один бот с локализацией через Bot API; отдельные боты по языкам — при выходе на отдельный рынок

- Статус: **принято** (2026-10-08)
- Контекст обсуждения: подсказка inline-режима в @BotFather (`/setinline`) задаётся одной строкой без языков — англоязычный пользователь видит русскую подсказку. Предложение владельца: один бэкенд, два бота (RU и EN), при необходимости — ещё локали.

## Что в Telegram локализуется, а что нет

| Что | Локализуется в одном боте? | Как |
|---|---|---|
| Ответы бота | да | язык пользователя (`users.locale`, словарь `src/bot/messages/*`) — уже есть |
| Меню команд | да | `setMyCommands` с `language_code` — уже делает `scripts/deploy.ts` |
| Описание («что умеет бот» до `/start`), короткое описание (профиль, шаринг) | да | `setMyDescription`, `setMyShortDescription` с `language_code` |
| Отображаемое имя бота | да | `setMyName` с `language_code` |
| **Подсказка inline-режима** | **нет** | только @BotFather `/setinline`, одна строка |
| **@username** | **нет** | один на бота |

## Варианты

### A. Один бот, локализация через Bot API (выбрано)
- Подсказка inline — двуязычная или нейтральная: «🗓 завтра 19:00 футбол · tomorrow 7pm» / «🗓 19:00 ⚽».
- `scripts/deploy.ts`: `setMyName`, `setMyDescription`, `setMyShortDescription` для `ru` и `en` (по умолчанию — `ru`).
- Цена: ~полчаса. Покрывает всё, кроме @username и подсказки inline.

### B. Отдельный бот на язык, общий бэкенд (отложено до R3)
**Что даёт:** подсказка inline на нужном языке; своё @username и имя для рынка (поиск, запоминаемость, маркетинг); раздельная витрина (описание, аватар, каталоги), возможно — свои условия/тарифы; отдельные лимиты Telegram (~30 сообщений/с на бота).

**Что усложняет** — многое в Telegram привязано к конкретному боту, а у нас семейные сценарии между людьми:
1. **Семья на разных ботах.** Писать человеку может только бот, с которым он начал диалог → у пользователя «домашний бот», и все исходящие не в ответ на апдейт (уведомления US-72, напоминания US-71, поручения US-91, эскалации, сводки US-70/93, алерты) маршрутизируются через бота получателя.
2. **Кнопки и правка сообщений** — только у бота-отправителя: карточки (`pending_actions`), поручения (`assignment_messages`), inline-токены — хранят бота.
3. **`file_id` у каждого бота свой** — переслушивание голосового (multimodal, вариант D) и вложения — через того же бота.
4. **Семейная группа** — ровно один бот на группу (иначе дубли), правило выбора; второй — вежливо уходит.
5. **Inline-карточка** русского бота у англоязычного друга ведёт в русского бота (deep link) — развилка.
6. **Ссылки** (приглашения в дом, OAuth, `start=add_…`) — от username конкретного бота.
7. **Пользователь в обоих ботах** — один Telegram id, два диалога: настройки, контекст, «последнее голосовое» — решить, один ли это пользователь.
8. **Инфраструктура:** токены и секреты вебхука на бота, маршрут `/telegram/<bot>/webhook`, `setWebhook`/команды/описания на бота, фейки и приёмка с несколькими ботами, админка и алерты по ботам.

**Изменения в коде (оценка 3–5 дней с тестами, риск средний — затрагивает все исходящие):**
- конфиг: список ботов `{key, token, webhookSecret, username, defaultLocale}`; `TelegramApi` — на бота;
- вход: вебхук на бота, ключ бота в inbox и `AppContext`;
- данные: `conversations.id` → `telegram:<bot>:<chatId>`, «домашний бот» у пользователя, бот у карточек/поручений/inline-токенов/`lastVoice`; миграция текущих записей в «ru»-бота;
- выход: единая точка «через какого бота писать получателю»;
- группы, деплой, фейки, раннер, админка — мультибот.

### C. Подготовка к B без второго бота (не сейчас)
Идентичность бота параметром (`TelegramApi` на бота, ключ бота в контексте), поле «через какого бота» в новых таблицах, все исходящие — через одну функцию выбора бота. ~1 день + миграция; сейчас почти ничего не даёт.

## Решение

- **Сейчас — A.** Двуязычная/нейтральная подсказка inline; локализованные имя и описания через Bot API при деплое.
- **B — при выходе на отдельный англоязычный рынок (R3)**, когда понадобятся своё @username и бренд: это решение про маркетинг, не про подсказку. Перед этим — C.
- Пересмотреть, если: (1) англоязычные пользователи заметно путаются из-за русского @username/подсказки; (2) появится маркетинговый запуск на EN-рынок; (3) понадобятся разные условия по рынкам.

## Последствия

- Код остаётся однобо́товым; новые таблицы с сообщениями/кнопками по возможности хранят минимум, нужный для будущей привязки к боту (chat id + message id уже есть).
- Действие владельца: обновить подсказку в @BotFather `/setinline`.
