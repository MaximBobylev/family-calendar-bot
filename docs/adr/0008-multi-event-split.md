# ADR-0008: Несколько событий в одном сообщении — делит наш код, LLM даёт названия; одна карточка-список

- Статус: **принято** (2026-10-11), техлид; владелец недоступен, продуктовые решения — [US-62](../user-stories.md#us-62-несколько-действий-в-одном-сообщении) «Решения R2», UX — [research/multi-event-scenarios.md](../research/multi-event-scenarios.md).
- Замер: [research/multi-event-eval.md](../research/multi-event-eval.md). План для разработчика: [research/multi-event-plan.md](../research/multi-event-plan.md).
- Связано: ADR-0005 п.3 (даты считает код), ADR-0004 (одно сообщение — одно AI-действие), ADR-0006 (переносимые тесты), tech-debt #6 (машина состояний карточки).

## Контекст

Сейчас несколько tool calls от LLM → интент `multiple` → «Давайте по одной». Для US-62 нужно: одно сообщение (своё / пересланное, текст / голос) → одна карточка со списком до 5 (своё) или 10 (пересланное) событий, переключатели, частичный сбой с «Повторить», отмена всей пачки.

Открытые вопросы продакта: как делить; где хранить список; как отменять пачку; идемпотентность; общий день vs `withConversationDay`; что такое «похожее»; ежегодное правило для дня рождения.

## Решение

### 1. Делит сообщение наш детерминированный делитель; LLM — названия и второе мнение о дате

Новый чистый модуль `src/bot/multi-split.ts`: текст → куски-дела по датам и границам (знаки, союзы «и / а / потом / and / then»), с правилами «не делить» (серия, интервал, «или», кусок без даты приклеивается к соседу) и перечислением («в пятницу и в субботу в 10 футбол» → два). Число дел и кусок даты каждого дела — от делителя. Ответ LLM (тот же один вызов, что и сейчас) сопоставляется с кусками по порядку: из вызова `create_event` берутся `title`, `calendar` и `start`/`when` как второе мнение о дате этого куска (`llmDateCheck` по тексту куска, как у одного события). Куску без пары — эвристическое название из текста.

Почему так:
- Замер: бесплатные модели теряют события (Nemotron, первое звено, — 4 из 12 фраз верно; Qwen — 11 из 24), всегда в сторону «оставить первое»; правило в промпте поднимает Qwen до 71 %, Nemotron — нет. Свой прототип — 24 из 24 по числу дел, без лишних делений.
- Даты — уже наш разбор (ADR-0005 п.3); граница дела почти всегда проходит между датами, а их мы находим сами (`extractDateSpans`). Модель, наоборот, портит `start` (кладёт туда название, дописывает общий день).
- Ноль дополнительных вызовов LLM: квота и лимит «одно сообщение — одно AI-действие» не меняются.

Защита от ложного деления: деление только по нашей дате или явному маркеру («ещё / также / а ещё», «also»); один ответ LLM «два вызова» без двух кусков в тексте ничего не делит. Кусок без дат и маркера всегда приклеивается к соседу. Корпус «делить / не делить» — `testdata/split/cases.yaml`, золотой, как `testdata/dates/`.

Многошаговый режим «отдельный вызов LLM на кусок» отвергнут: N вызовов на сообщение при 50 запросах/сутки OpenRouter.

### 2. Делитель — до поправок интента

В `routeIntent` делитель запускается раньше `assignOverride` и `effectiveIntent`: сейчас «удали» в любом месте фразы превращает создание в удаление, а ответственный «отводит папа» при `multiple` схлопывает сообщение в первое событие (`assignOverride`). Многособытийный путь включается, когда в сообщении ≥ 2 кусков-созданий, поручения (`assign_task` по тексту) в нём нет, а LLM вернула `create_event`, `multiple` или `unsupported`. Кусок с глаголом изменения / удаления / показа («удали…», «перенеси…», «покажи…») — не создание: строка «⏭ Не сделано»; кусок без своего глагола после такого наследует его («перенеси обед на 14 и созвон на 15» — оба изменения → «по одной», как сейчас).

### 3. Хранение: одна строка `pending_actions` kind `multi`, миграций нет

Payload — список до 10 элементов с готовыми `CreateOption` (как у карточки одного события), состоянием переключателя, пометками (⚠️ похожее, ⏰ пересечение, ❓ вопрос, день рождения), общим флагом «каждый год» и результатом выполнения. `callback_data` — `pa:<id16>:<выбор>`, выбор `t0`…`t9` / `y` / `c` / `x` / `r` — ≤ 22 байт из 64.

Переключатели **не захватывают** карточку (`claimCard` переводит её в `executing`): отдельная запись payload с compare-and-swap по `payload_json` при `status = 'open'` (как `mergeDialogState`), затем `editMessageText` (ошибку «message is not modified» `telegram/api.ts` уже глотает). «Создать» / «Повторить» — через обычный `claimCard`, kind в `RETRYABLE`.

### 4. Идемпотентность: id события = id карточки + номер строки

`idempotencyKey = <id карточки><номер строки 0–9>` — как у `.ics` (`confirmIcs`). Повтор после сбоя, повторное нажатие, умерший обработчик (`executing` → retry по tech-debt #6) не создают дубль: Google ответит 409 на свой id — это успех (`calendar-api.ts`). Частичный сбой: созданные помечаются в payload, карточка возвращается в `open` с кнопкой «Повторить (N)» — повтор создаёт только несозданные с теми же ключами. Созданное не откатываем (осознанное исключение из US-14, решение продакта).

### 5. Отмена пачки: одна запись отмены со списком

`UndoRecord` получает вариант `{ kind: "create_many", items: { ref, etag?, title }[] }`. Одна запись — одна кнопка «↩ Отменить все (K)» и одно «отмени последнее» (правило «отменяется только последнее действие» сохраняется: пачка — одно действие). Удаление по каждому событию с etag; изменённое после создания — не трогаем и называем («Не удалил «Футбол» — его уже изменили»), удалённое в Google — молча считаем удалённым. После «Повторить» запись отмены пересоздаётся на все созданные события.

### 6. Общий день — `withConversationDay` по предыдущему делу того же сообщения

Время без дня у дела № i > 1 берёт день дела № i − 1 (уже разрешённого нашим парсером) той же функцией `withConversationDay(point, prevDay, today)`; у первого дела — как сейчас день разговора US-60. Общий день сильнее дня разговора. LLM-мнение о дате для такого куска не спрашиваем (как сейчас при дне разговора).

### 7. «Похожее» — `titleScore` из `src/calendar/match.ts` (то же, что связывание поручения US-91)

Событие того же дня в том же календаре с `titleScore(новое, существующее) ≥ 0.5`; со временем — не дальше 3 часов (как `findEventToLink`). Один `listEvents` на весь промежуток дат карточки (он же даёт ⏰ пересечения). Дубль внутри сообщения — одно событие (одинаковые нормализованное название и момент).

### 8. День рождения / годовщина → ежегодное событие на весь день

Название или кусок совпадает с `день рождени|ДР|годовщин|юбиле|birthday|anniversary`, дата без времени → `allDay` + серия `FREQ=YEARLY` (готовые `toRRule` / `describeRecurrence`), одна кнопка «🔁 Каждый год: да / нет» на все такие строки карточки. Со временем — разовое событие. То же правило — для карточки одного события (уточнение US-31), там кнопка та же.

## Альтернативы

| Вариант | Почему нет |
|---|---|
| A. Делит LLM (несколько tool calls), код только разбирает даты по `start` каждого вызова | Замер: теряет события в 54–67 % фраз на моделях прода; `start` модели ненадёжен как граница куска |
| B. A + сторож: «нашли больше дат, чем вызовов — спросить «по одной»» | Безопасно, но базовый случай владельца (два ДР в пересланном) у Nemotron не пройдёт; сторож всё равно требует делителя — тогда проще делить им |
| C. Отдельный tool `create_events` с массивом | Маленькие модели хуже держат массивы в аргументах (обрыв JSON после `title`, llm-intents-eval.md); меняет схему для всех сообщений; проблема «потеряла» остаётся |
| D. Вызов LLM на каждый кусок | ×N вызовов при 50 запросах/сутки OpenRouter и 10 000 neurons |
| E. Хранить каждое событие отдельной карточкой | Ломает «одна карточка, одна главная кнопка», отмену пачки и правило US-05 «новая команда аннулирует карточку» |

## Последствия

- Новые модули: `src/bot/multi-split.ts`, `src/bot/multi-logic.ts`, `src/bot/multi-view.ts`, `src/bot/multi-event.ts`, `src/bot/messages/multi.ts`; изменения — `route-intent`, `dialog`, `callbacks`, `undo`, `forwarded`, `ingest`, `conversations`. Подробно — план.
- Миграций нет: всё в `pending_actions.payload_json` и `dialog_state`.
- Правило деления в промпте (`M`) — необязательное улучшение названий/пар для Qwen; включать в прод только после регрессионного замера на всём `testdata/nlu/intents.yaml`.
- Риски: ложное деление на запятых адресов и уточнений (держит корпус `testdata/split/`); лимит подзапросов Worker (50) при 10 событиях с ретраями — сбой ловится по строке и уходит в «Повторить»; эвристические названия хуже LLM, когда пара не нашлась.
