# Технический долг и ревью (2026-10-05)

Три независимых ревью (агенты, только чтение): архитектура и качество кода, безопасность, надёжность и эксплуатация. Ниже — сводка: что исправлено сразу и что осталось, по приоритету.

**Общая оценка.** Критичных уязвимостей нет: SQL только prepared statements, HTML в Telegram экранирован, OAuth state одноразовый и привязан к пользователю, данные пользователей изолированы, refresh token — AES-GCM. Портируемость (ADR-0006) соблюдена: часы внедряются, URL из конфига. Главные проблемы были в **семантике сбоев** (тихая потеря апдейтов, «Уже сделано» на несделанном, «Google не отвечает» на чужие ошибки) и **отсутствии ретеншна**.
