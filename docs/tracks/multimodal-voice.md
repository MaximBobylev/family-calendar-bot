# Трек: голосовая команда одним мультимодальным вызовом

- Статус: **вариант D (эскалация) реализован** 2026-10-05: `src/voice/`, сценарии `acceptance/scenarios/20-voice-rehear.yaml`. Постоянный путь (вариант B) — по замеру на реальных голосах; синтетика с шумом (2026-10-06, [voice-synth-eval.md](../research/voice-synth-eval.md)) — пока «за D».
- Повод: внешняя оценка «Gemini Flash-Lite: аудио → транскрипт + вызов инструмента за один запрос» (сверена ниже с актуальными данными).
- Связано: ADR-0002 (цепочки провайдеров), docs/research/llm-intents-eval.md (замер текстового разбора), US-10 (голос).

## Сейчас

```
голосовое (OGG/Opus) → STT: Groq Whisper → Workers AI Whisper     ~0,5–1 с
                     → сразу «🎙 <текст>» пользователю               ← сигнал «услышал, работаю»
                     → LLM: OpenRouter Gemma 4 → Workers AI Qwen3   ~0,6–3 с
                     → даты/длительность — детерминированно из текста (extract.ts)
                     → карточка с кнопками (осторожный режим)
```

Слабые места: Whisper искажает имена и редкие слова («Созван спеть и» вместо «Созвон с Петей»), подсказки ему (`initial_prompt`) не помогли (замер 2026-10-04); два последовательных сетевых вызова.

## Синтетика с шумом (2026-10-06) — [research/voice-synth-eval.md](../research/voice-synth-eval.md)

Набор из 158 голосовых (edge-tts: 3 голоса RU, 2 голоса EN; условия: чисто, розовый шум 10 дБ, гул голосов с телефонной полосой 5 дБ; 3 файла без речи). Сравнивали текущий путь A (Whisper + Nemotron) и B (`gemini-3.5-flash-lite` одним вызовом).
- Чисто и розовый шум: интент 100 % у обоих. B точнее в именах («Петей», «тимлидом» — Whisper ошибается в 6 из 6), но **нормализует время с ошибкой** («полвосьмого» → «8:00»/«полдевятого» — 4 из 6) и однажды перевёл английскую фразу на русский.
- Гул голосов: оба плохи (интент 18 % против 33 %). B 6 раз выдал уверенную неверную команду, A — 1 раз.
- Без речи: 3 из 3 у обоих.
- Задержка на бесплатном Gemini: p50 1,3 с, но 10 % вызовов — таймаут 25 с. У A p95 2,1 с.

Вывод: остаёмся на D, B не включаем; сначала усилить дословность в `VOICE_RULES` и проверить на живых голосах.

## Главные вопросы дизайна

### 1. Не потерять ранний «🎙 …»

Сейчас распознанный текст — первый ответ за ~1 с. Один мультимодальный вызов отдаёт транскрипт вместе с интентом.

| Вариант | UX | Цена/сложность |
|---|---|---|
| A. Только мультимодальный вызов | «🎙» приходит вместе с карточкой (1–3 с); до этого — «печатает…» | проще всего |
| **B. Параллельно: Whisper (быстрый) + мультимодальный** | «🎙 <Whisper>» через ~0,5–1 с, как сейчас; интент — из мультимодального; если его транскрипт отличается — правим сообщение «🎙» на его версию (`editMessageText`) | +$0.00006 на команду; бесплатный «теневой» замер расхождений на каждом голосовом; естественный откат: упал мультимодальный → Whisper-текст в обычный текстовый разбор |
| C. Мультимодальный только как STT, разбор — как сейчас | ранний «🎙» сохраняется | выигрыша в задержке нет; только качество распознавания |

**Рекомендация: B.** Сохраняет сигнал «услышал», даёт отказоустойчивость (две независимые ветки) и постоянную телеметрию качества.

### 2. Дословность транскрипта

Даты считаются детерминированно из текста (extract.ts) — модель не должна «улучшать» фразу.
- В tool-схему — обязательное поле `transcript`: «verbatim, as spoken; keep numbers as heard; do not convert relative dates; do not fix grammar».
- Нормализация в цифры («пол третьего» → «14:30») сама по себе не страшна — парсер понимает цифры; опасна **неверная** нормализация (утро/вечер, «на 11» → «23:00»). Ловим замером: даты из транскрипта мультимодальной модели vs из эталона.
- Даты по-прежнему только из транскрипта, не из аргументов модели — граница ADR-0005 не меняется.

### 3. Тишина, шум, обрывки

Мультимодальная модель может «додумать» команду из шума. Защита:
- в tools — явный вариант `no_speech` («ничего не сказано / неразборчиво»);
- при варианте B: Whisper вернул пусто/галлюцинацию **и** мультимодальный уверен → не выполняем, переспрашиваем («Не расслышал, повторите»);
- осторожный режим: любое действие — через карточку с кнопкой; ошибочно «услышанное» не выполнится молча.

### 4. Формат аудио

Нативный Gemini API (`generateContent`, `inline_data` `audio/ogg`) принимает Opus — **основной путь**, без перекодирования в Worker. OpenRouter `input_audio` с `format: "ogg"` — проверить на этапе 1; если Opus не принимается, кандидаты через OpenRouter отпадают (перекодирование Opus → WAV в Worker — WASM-декодер, дорого по CPU-времени).

## Вариант D: эскалация по сигналам (идея 2026-10-05, после живого лога)

Мультимодальный разбор — не на каждое голосовое, а когда текстовый путь, скорее всего, ошибся. Лог: «Рисование Аня от Мини» ×2 — человек повторяет ту же фразу, Whisper снова режет «отмени».

Сигналы (детерминированные, в пределах окна контекста 15 мин, только для голосовых):
1. **Явное «не так»**: «неправильно», «не то», «не так», «нет, я сказал(а) …», «ты не понял(а)» — сразу после ответа бота на голосовое.
2. **Повтор**: новое голосовое, чей транскрипт похож на предыдущий (общие значимые слова, `titleScore`/расстояние) — человек переговаривает.
3. **Тупик текстового пути на голосе**: `unsupported`, «не нашёл встречу», «не понял, за какой период» — ответ бота на голосовое, которое по длительности/словам похоже на команду.

Действие: взять **аудио того же сообщения** (Telegram `file_id` можно скачать повторно — хранить ничего не нужно) → мультимодальный вызов → «🎙 Переслушал: <транскрипт>» + обычная карточка. Для сигнала 2 — переслушать **новое** голосовое (оно свежее), для 1 — предыдущее.

Плюсы: мультимодальный вызов — только на ~5–10% голосовых (дёшево, бесплатные лимиты Google/OpenRouter хватает); не нужен параллельный путь на каждое сообщение; задержка обычного пути не меняется. Минус: первый ответ остаётся ошибочным — человеку приходится сказать «не так» или повторить. Хорошо сочетается с B (B — когда выберем постоянный путь; D — уже сейчас, малой кровью).

Хранить: в `dialog_state` — `lastVoice: { fileId, transcript, at, outcome }` (outcome: ok / unsupported / not_found / …).

## Архитектура (если замер «за»)

- Новый вид провайдера в цепочке: `VOICE_CHAIN` — `[{name, kind: "gemini" | "openai-audio", baseUrl, apiKey, model}]`; секрет собирает `scripts/deploy.ts` (ключ `GEMINI_API_KEY` или через OpenRouter).
- `src/voice/` — `understandVoice(audio, context) → {transcript, intent, noSpeech}`: тот же реестр tools (src/nlu/intents.ts) + поле `transcript` + `no_speech`; разбор ответа — общий `intentFromCalls`.
- Конвейер голосового в `handle-update.ts` (заодно — шаг к tech-debt #9):
  ```
  parallel:
    stt  = transcribeChain(STT_CHAIN)        → «🎙 …» сразу
    mm   = understandVoice(VOICE_CHAIN)      → {transcript, intent}
  if mm ok and not noSpeech:  intent = mm.intent; text = mm.transcript; при расхождении — правка «🎙»
  elif stt ok:                текстовый разбор stt.text (как сейчас)
  else:                       «Не могу распознать голос»
  ```
- Учёт: одна запись `kind=voice` (или две — stt и llm — как сейчас) с провайдером и стоимостью; лимиты — как у голосового сейчас (STT + LLM).
- Журнал: оба транскрипта (Whisper и мультимодальный) — в `result_json` → в админке колонка «расхождение»; это и есть теневой замер.
- Фейки (ADR-0006): `/voice/…` эндпоинт, отвечающий по содержимому «аудио» фикстурой `{transcript, tool, args}`; сценарии: оба работают, мультимодальный упал → текстовый разбор, Whisper упал → только мультимодальный, тишина (`no_speech`), расхождение транскриптов → правка «🎙».

### Критерии решения (этап 2)

Переходим, если на нашем наборе мультимодальный кандидат:
- точность полей интента ≥ текущего пути (Whisper + Gemma 4), и
- WER транскрипта не хуже Whisper (особенно имена), и
- ни одной «команды из тишины» на шумовом наборе (с `no_speech`), и
- p95 «до карточки» ≤ текущего (ориентир ≤ 3–4 с; ранний «🎙» остаётся от Whisper).

## Риски и открытые вопросы

1. **Данные на бесплатном тарифе** Google/OpenRouter идут на обучение — только для разработки; до беты — платный тариф (дёшево, см. экономику) и строка в privacy policy (ADR-0002).
2. **География Gemini API**: бесплатный тариф недоступен пользователям из ЕЭЗ/UK/Швейцарии; проверить для нашей юрисдикции (грузинское ИП, бразильская карта) и аудитории перед бетой.
3. **Opus через OpenRouter** — не подтверждён; если нет — Gemini только напрямую (ещё один ключ и адаптер `kind: "gemini"`).
4. **Расхождение транскриптов** в варианте B может смущать («🎙» поменялся) — правим тихо, без нового сообщения; если раздражает — показывать только итоговый.
5. **Бюджет замеров**: бесплатные лимиты (OpenRouter free — 50 запросов/сутки без кредитов, AI Studio — по квотам проекта) — замер дробить по дням или положить $10 на OpenRouter. Урок 2026-10-05: перед замером считать вызовы против квоты и не гонять его на аккаунте прода.
