# Пользовательские сценарии

Формат: **US-xx** — история, примеры фраз, критерии приёмки (AC), граничные случаи.
Пометка `[допущение]` — решение, принятое по умолчанию, требует подтверждения (см. [open-questions.md](open-questions.md)).
Общие правила разбора дат и времени — в [date-rules.md](date-rules.md).

**Принцип продукта.** Бот — это быстрый способ поправить календарь там, где вы и так проводите время: пришло уведомление, вспомнили о встрече — подвинули, не выходя из Telegram. Поэтому разумные умолчания важнее тонкой настройки: кому нужны тонкости (например, уведомления участникам), тот идёт в сам Google Календарь.

## Эпик 1. Подключение и настройки

### US-01. Первый запуск
Как новый пользователь, я хочу понять, что умеет бот и как начать, чтобы быстро подключить календарь.

- `/start` → приветствие, 2–3 примера фраз, кнопка **«Подключить Google Календарь»**.
- Если календарь уже подключён — краткая справка и примеры.

**AC**
- Первым делом проверяется доступ (allowlist / entitlement, см. ADR-0001, ADR-0004). Нет доступа → вежливый отказ, ни STT, ни LLM не вызываются.
- Любое сообщение от неподключённого пользователя → предложение подключить календарь, интент не распознаётся.
- Бот работает только в личных чатах `[допущение]`; в группе отвечает «напишите мне в личку».

### US-02. Привязка Google-аккаунта
Как пользователь, я хочу дать боту доступ к своему календарю в пару кликов.

**Поток**
1. Пользователь жмёт кнопку → получает одноразовую ссылку `https://<worker>/oauth/start?state=<подписанный токен с внутренним user_id, TTL 10 мин>`.
2. Стандартный экран согласия Google (scopes — см. [ADR-0001](adr/0001-audience-and-google-oauth.md)), `access_type=offline`, `prompt=consent` — иначе при повторной привязке Google не выдаст refresh token.
3. Callback на Worker → обмен code на refresh token → сохранение (зашифрованно) → страница «Готово, вернитесь в Telegram» с deep-link в бота.
4. Бот сам пишет в чат: «Календарь `ivan@gmail.com` подключён. Часовой пояс: Europe/Moscow» (email = id основного календаря из `calendarList`).

**AC**
- Ссылка одноразовая и протухает; повторное использование → понятная ошибка.
- Нельзя привязать свой Google к чужому пользователю бота (state подписан).
- Отказ на экране согласия → бот сообщает, что доступ не выдан, и предлагает повторить.
- Повторная привязка **другого** Google-аккаунта заменяет предыдущую (в MVP один аккаунт на пользователя; модель данных допускает несколько — ADR-0003). Алиасы старого аккаунта удаляются.
- Один Google-аккаунт у двух пользователей бота — допустимо, привязки независимы.

**Граничные случаи**
- Доступ отозван в Google → `invalid_grant` → сообщение и кнопка «Переподключить».

### US-03. Отключение и удаление данных
- `/disconnect` → подтверждение → revoke токена в Google + удаление всех данных пользователя, включая журнал (US-13).

### US-04. Настройки
- `/settings` — меню с inline-кнопками: аккаунт, часовой пояс (US-07), календари и алиасы (US-06), длительность по умолчанию `[допущение: 1 час]`, напоминания по умолчанию (для обычных событий и для событий на весь день отдельно), режим подтверждений, язык ответов, дайджесты и напоминания в Telegram (US-70, US-71).
- Любую настройку можно менять голосом: «по умолчанию ставь встречи на 30 минут», «не присылай вечерний дайджест».
- Смена **режима подтверждений** голосом сама требует подтверждения кнопкой (защита от ошибки распознавания).

**Напоминания по умолчанию**
- Хранятся в настройках бота и применяются только к событиям, которые создаёт бот. Дефолты Google не трогаем.
- Не заданы → событие создаётся с `useDefault=true`.
- Для событий на весь день — отдельная настройка `[допущение: по умолчанию — без напоминаний]`, иначе «за 15 минут» сработает в 23:45 накануне.

### US-05. Режим подтверждений

| Операция | Осторожный (по умолчанию) | Доверительный |
|---|---|---|
| create / modify / reminders одного события | карточка-подтверждение | выполняется сразу + «↩ Отменить» |
| создание серии, изменение серии `following` / `all` | подтверждение | подтверждение |
| удаление (любое), массовые операции | подтверждение | подтверждение |

**Обязательное подтверждение в любом режиме**, если сработал хотя бы один детерминированный триггер:
- у слота даты/времени стоит `ambiguous` (см. date-rules.md) — тогда вместо одной кнопки показываются варианты;
- ссылка на событие разрешилась в >1 кандидата;
- календарь сопоставлен нечётко (не точное совпадение алиаса/названия);
- ответ дал fallback-провайдер LLM;
- событие найдено с изменённым `etag` после показа карточки (US-63).

**AC: кнопки и идемпотентность**
- Каждая карточка привязана к id черновика (pending action), хранящемуся на сервере; в `callback_data` — только короткий id.
- Повторная доставка одного `update_id` Telegram не приводит к повторному выполнению.
- Повторное нажатие уже выполненной кнопки → «Уже сделано», без повторного действия.
- Новая команда при открытой карточке аннулирует её: сообщение карточки редактируется в «Отменено».
- Карточка старше окна контекста (US-60) → «Карточка устарела, повторите команду».

### US-06. Несколько календарей и алиасы
Как пользователь с личным, рабочим и общим с супругой календарями, я хочу говорить «поставь в общий» и не думать про остальное.

**Поток**
- После привязки бот загружает все календари из `calendarList` и предлагает выбрать **календарь по умолчанию** среди тех, куда можно писать (`accessRole` ∈ {`writer`, `owner`}).
- Каждому календарю — один или несколько алиасов на любом языке: «общий», «семейный», «family».
- Голосом: «Назови календарь Family Budget "семейный"», «Сделай рабочий календарём по умолчанию».

**AC**
- Календарь не назван → календарь по умолчанию.
- Алиас ищется нечётко (падежи: «в общем календаре», «из рабочего»); не найден → календари кнопками.
- При >1 календаре в карточках и списках видно, в каком календаре событие.
- Календари только для чтения (праздники, дни рождения, подписные) участвуют в чтении и дайджестах, но не используются для записи и не предлагаются как календарь по умолчанию.
- Список календарей обновляется по команде, раз в сутки и автоматически, если названный календарь не найден.

**Пример для семьи:** у каждого супруга свой Telegram и своя привязка Google; общий календарь расшарен обоим с правом записи, каждый задаёт ему свой алиас.

### US-07. Часовой пояс и поездки
> «Я в Тбилиси до воскресенья», «Я в Тбилиси», «Я вернулся», «Я переехал в Тбилиси», «Какой у меня часовой пояс?»

У пользователя есть **домашний пояс** (из Google при привязке, хранится в настройках бота) и необязательный **пояс поездки** — временный override.

**AC**
- «Я в Тбилиси» → бот определяет пояс (`Asia/Tbilisi`) и спрашивает кнопками: **«На время поездки»** / **«Навсегда»** (+ «До какого числа?», если дата не названа — можно пропустить).
- «На время поездки» → включается override, домашний пояс сохраняется.
- «Навсегда» / «я переехал» → меняется домашний пояс, override снимается.
- Возврат:
  - «Я вернулся» → override снимается, бот подтверждает: «Вернул Europe/Moscow».
  - Если у поездки есть дата окончания — в этот день бот спрашивает: **«Вернулись? Вернуть Europe/Moscow»** / **«Ещё нет»** / **«Оставить Asia/Tbilisi навсегда»**.
  - Если даты нет — тот же вопрос раз в `[допущение: 7 дней]`.
- Текущий пояс (и что это поездка) виден в `/settings` и в шапке дайджестов во время поездки.
- Все относительные даты, дайджесты и напоминания считаются в текущем поясе пользователя.
- Если пояс пользователя отличается от пояса календаря/события — в карточке показываются оба времени.
- У повторяющихся событий всегда задаётся IANA-пояс (`start.timeZone`), чтобы при переходе на летнее время локальное время сохранялось.

## Эпик 2. Ввод и распознавание

### US-10. Голосовое сообщение
**AC**
- Индикатор `typing…` обновляется каждые ~4 сек до ответа (Telegram гасит его через ~5 сек).
- Ответ на голосовое — ≤ 8 сек в p95 `[допущение]`.
- Распознанный текст показывается отдельным сообщением «🎙 …» сразу после распознавания — до долгой обработки (реализация 2026-10-04).
- Длина `[допущение: до 60 сек]`; длиннее — вежливый отказ без вызова STT.
- Пустой результат, шум или известная «галлюцинация на тишине» («Продолжение следует…», «Субтитры сделал…» — стоп-лист) → «Не расслышал, повторите». Для Workers AI Whisper — `vad_filter`; в `initial_prompt` передаются алиасы календарей и частые слова.
- Поддерживаемые типы: `voice` и `audio`. `video_note` и прочее → «Пришлите голосовое или текст» `[допущение]`.
- **Пересланное** голосовое/сообщение (`forward_origin`) не исполняется как команда: бот предлагает «Создать событие из этого?» с карточкой.
- Отредактированные сообщения (`edited_message`) игнорируются.

### US-10a. Языки
- Команды на русском, английском и смешанные («созвон по sync'у с тимлидом в 3pm»).
- Whisper — автоопределение языка.
- Ответы — всегда текстом, на языке из настроек. **По умолчанию — русский** независимо от языка Telegram (решение 2026-10-04); смена — в `/settings`.
- Названия событий сохраняются как распознаны, без перевода. Транслитерация («синк» вместо «sync») допустима `[допущение]`.

### US-11. Текстовое сообщение
- Тот же пайплайн без STT.

### US-12. Непонятный или неподдерживаемый запрос
- Не про календарь → «Я умею только работать с календарём» + примеры.
- Не хватает данных («поставь встречу») → уточняющий вопрос по шаблону для недостающего слота. Ответ дополняет тот же черновик.
- Несколько команд в одном сообщении (MVP) → «Давайте по одной» и ничего не выполняется.

### US-13. Журнал распознанных текстов
Как разработчик, я хочу видеть, что бот услышал и как разобрал.

- Сохраняем: текст, провайдер/модель STT и LLM, результат разбора, итог (выполнено / отменено / ошибка), время обработки, расход (секунды аудио, токены) — общая запись с учётом использования (ADR-0004).
- Аудио не храним.
- Срок хранения `[допущение: 90 дней]`; удаляется при `/disconnect`. Если фраза нужна для тестового набора — копируется вручную в анонимизированном виде.
- Доступ — только у владельца бота. Второй пользователь (супруга) знает и согласен; для платной версии — пункт в privacy policy.

### US-14. Ошибки и деградация
Ничего не выполняется частично: либо действие сделано целиком, либо не сделано и пользователь об этом знает.

| Ситуация | Что видит пользователь |
|---|---|
| Событие удалено извне (404/410) | «Эта встреча уже удалена» |
| Нет прав на календарь/событие (403) | «Нет прав менять эту встречу» |
| Квота Google (403 rateLimit / 429) | «Google просит подождать, повторите через минуту» |
| Google недоступен (5xx, после ретраев) | «Google Календарь не отвечает, попробуйте позже» |
| Оба STT-провайдера недоступны | «Не могу распознать голос сейчас, напишите текстом» |
| Оба LLM-провайдера недоступны | «Не могу разобрать команду сейчас, попробуйте позже» |
| Не удалось скачать голосовое | «Не смог получить голосовое, пришлите ещё раз» |
| Токен Google отозван | см. US-02 |

## Эпик 3. Чтение расписания

### US-20. Что у меня сегодня / завтра / на неделе
> «Какие встречи сегодня?», «Что у меня завтра после обеда?», «Покажи неделю», «Что в пятницу в family календаре?»

**AC**
- Источник — все подключённые календари, включая календари только для чтения (праздники, дни рождения), если конкретный не назван.
- Строка события: время (в поясе пользователя), название, длительность, место/ссылка на звонок; при >1 календаре — метка календаря.
- События на весь день — сверху.
- Фильтры `[допущение]`: отклонённые (`responseStatus=declined`) скрываются; «свободен» (`transparent`) показываются с пометкой; `workingLocation`, `focusTime` скрываются; `outOfOffice` показывается.
- Пустой период → «Встреч нет 🎉».
- Неделя — сгруппирована по дням. Если ответ не помещается в 4096 символов — несколько сообщений; нумерация событий сквозная (для US-60).
- Интервалы «утро», «после обеда», «на неделе» — по date-rules.md.

### US-21. Следующая / конкретная встреча
> «Какая у меня следующая встреча?», «Когда встреча с Петей?»

- «Следующая» = ближайшая, которая ещё не началась; идущая сейчас упоминается отдельно («сейчас идёт: …»). События на весь день не считаются.
- Поиск по названию/описанию/участникам — **в коде**: `events.list` по диапазону `[допущение: 30 дней вперёд]` + нечёткое/морфологическое сопоставление («Петей» ↔ «Петя»). Параметр `q` Google для этого не годится.

### US-22. Свободное время (P2)
> «Когда я свободен в четверг?», «Найди час на этой неделе»

- Занятость считается по `events.list` (с выбранными scopes `freebusy.query` недоступен — ADR-0001). Рабочие часы `[допущение: 9–19, настраивается]`.

## Эпик 4. Создание событий

### US-30. Создать разовое событие
> «Поставь встречу на среду в 12», «Созвон с Петей завтра в 15:30 на полчаса», «Обед в пятницу с часу до двух»

**AC**
- Даты и время разрешаются по [date-rules.md](date-rules.md), неоднозначные случаи — кнопками с вариантами.
- Нет длительности → длительность по умолчанию. Событие через полночь допустимо.
- Календарь не назван → календарь по умолчанию.
- Карточка (по режиму, US-05): название, календарь, дата, время, длительность, напоминания, повторение, пересечения + **Создать / Изменить / Отмена**.
- После создания — ссылка на событие.
- Применяются напоминания по умолчанию из настроек бота, если не сказано иное.
- Ссылка Google Meet не добавляется, если не попросили («с ссылкой на Meet») `[допущение]`.
- Пересечения проверяются по календарю, в который создаётся событие, и по календарю по умолчанию `[допущение]`; показываются предупреждением, создать можно.
- Время в прошлом → переспросить.

**Название не задано** («поставь встречу на среду в 12»)
- Создание не блокируется: название по умолчанию — «Встреча» / «Meeting» по языку интерфейса `[допущение]`.
- После создания бот спрашивает: «Как назвать встречу?» сообщением с `ForceReply` (кнопку «Оставить так» Telegram в одном сообщении с ForceReply не допускает — вопрос можно просто проигнорировать).
- Название принимается двумя способами:
  - **явная команда** в любой момент, без reply: «назови её "Ревью дизайна"», «используй название …», «переименуй в …» — это `modify_event` с `event_ref: {last: true}`;
  - **голый ответ** («Созвон с Петей») засчитывается как название **только** если это reply на вопрос бота — иначе такое сообщение разбирается как новая команда.
- Любая другая команда снимает вопрос.
- Ответа нет → остаётся «Встреча».

### US-31. Событие на весь день
> «Отпуск с 10 по 20 ноября», «Завтра день рождения мамы»

**AC**
- Диапазон включающий: «с 10 по 20» → `start.date=10`, `end.date=21` (в Google `end.date` исключающая).
- Напоминания — по отдельной настройке для событий на весь день (US-04).
- «День рождения» / «годовщина» → в карточке кнопка «Повторять каждый год».

### US-32. Повторяющееся событие (MVP)
> «Каждый понедельник в 10 планёрка», «Стендап по будням в 11 до конца года», «Раз в две недели по четвергам ретро», «Every first Monday of the month at 9 — budget review»

**AC**
- Частоты: ежедневно, по будням, еженедельно (несколько дней), раз в N недель, ежемесячно (по числу, «первый/последний <день недели>», «последний день месяца» = `BYMONTHDAY=-1`), ежегодно.
- Окончание: без конца / до даты / N раз.
- Карточка: правило человеческим языком + 3 ближайшие даты.
- «31 числа каждого месяца» → предупреждение, что Google пропустит короткие месяцы, и предложение «последний день месяца».
- Создание серии подтверждается в любом режиме.
- Часовой пояс задаётся явно (US-07).

## Эпик 5. Изменение событий

Общие правила для US-40…US-43:
- **Не организатор** (`organizer.self != true`): перенос и изменение деталей запрещены с объяснением («вы не организатор — попросите организатора»). Напоминания менять можно. «Удали / отмени» → **отклонение приглашения**; карточка явно говорит: «Встреча не удаляется — вы отклоняете приглашение, организатор получит ответ».
- **Уведомления участникам:** если пользователь организатор и есть другие участники — **всегда** `sendUpdates=all`, в карточке строка «Участники получат уведомление». Тонкая настройка — в самом Google Календаре (см. принцип продукта).
- **Параллельные правки:** перед выполнением событие перечитывается; если `etag` изменился с момента показа карточки — карточка показывается заново (US-63).

### US-40. Перенести событие
> «Перенеси встречу с Петей на завтра», «Сдвинь созвон в 15 на час позже», «Перенеси следующую встречу на пятницу на то же время», «Перенеси обед в общий календарь»

**AC**
- Перенос задаётся одним из способов (intents.md, `modify_event`): новое абсолютное время, сдвиг («на час позже»), новая дата с сохранением времени, новое время с сохранением даты. Итоговое время считает код после нахождения события.
- Несколько кандидатов → кнопки (до 5, дальше «Уточните»). Не найдено → «Не нашёл …, вот что есть на этот день».
- Карточка «Было → Стало». Длительность сохраняется.
- Перенос в другой календарь — `events.move`.
- Повторяющееся событие → US-43.

### US-41. Изменить детали
> «Переименуй завтрашнюю встречу в "Ревью дизайна"», «Добавь к встрече в 12 описание …», «Сделай встречу в среду на полтора часа», «Добавь место: кафе Пушкин»

**AC**
- Меняются только названные поля; карточка «Было → Стало» по изменённым полям.
- Изменение длительности сохраняет начало.

### US-42. Изменить напоминания
> «Поставь напоминания за час и за сутки до встречи в среду», «Убери напоминания с обеда», «По умолчанию напоминай за 15 минут»

**AC**
- Для события — `reminders.overrides` (`useDefault=false`), тип popup; «на почту» → email.
- Ограничения Google: до 5 напоминаний, каждое ≤ 40320 минут (4 недели) — при превышении объяснить.
- «По умолчанию …» → настройка бота (US-04).

### US-43. Изменение повторяющихся событий (MVP)
> «Перенеси планёрку в этот понедельник на 11», «Перенеси все планёрки на 11», «Со следующей недели стендап в 10:30», «Планёрка теперь по вторникам», «Удали планёрку совсем»

**AC**
- Охват из фразы: «в этот понедельник» → `this`; «теперь», «с …», «совсем» → `following` от ближайшего будущего вхождения; «все» → `all`. Не понятно → кнопки **Только это / Это и следующие / Все**.
- `this` → изменение экземпляра.
- `following` → у старой серии `UNTIL` перед точкой разделения + новая серия. Карточка предупреждает: отдельно изменённые вхождения после точки разделения будут потеряны.
- `all` → изменение мастер-события; карточка прямо говорит, что **прошлые вхождения тоже изменятся**.
- Смена дня недели сдвигает и дату начала серии на первое подходящее вхождение.
- `following` и `all` подтверждаются в любом режиме. То же для напоминаний и удаления.

## Эпик 6. Удаление

### US-50. Удалить событие
> «Отмени встречу в среду в 12», «Удали все встречи на завтра»

**AC**
- Всегда подтверждение с перечнем удаляемого.
- Массовое удаление (по диапазону) — подтверждение с количеством; при >10 событиях — список свёрнут.
- Есть участники и пользователь организатор → «Участники получат уведомление об отмене» (`sendUpdates=all`).
- Пользователь не организатор → «Отклонить приглашение» с явной пометкой, что встреча не удаляется (правила эпика 5).

## Эпик 7. Диалог и удобство

### US-60. Контекст разговора
> «Что у меня завтра?» → «Перенеси вторую на час позже»
> «Создай встречу в среду в 12» → «А, нет, в 13»

- Бот помнит последний показанный список, последнее созданное/изменённое событие и открытый черновик.
- Окно контекста = окно отмены (US-61) = **15 минут** `[допущение]`, один параметр.
- Контекст хранится по паре (чат, пользователь) — ADR-0003.

### US-61. Отмена последнего действия
> «Отмени последнее», кнопка «↩ Отменить» под результатом.

**AC**
- Доступна 15 минут для последнего действия.
- Отменяемо: create (удаление созданного), modify/move, напоминания, изменение экземпляра серии (`this`), `all` для серии (возврат мастер-события).
- **Не отменяемо** (кнопка не показывается, объяснение по запросу): удаление события с участниками или созданного не ботом (повторное создание даст новый id, потеряет Meet, разошлёт приглашения); разделение серии (`following`); массовое удаление.
- Перед отменой проверяется `etag`: если событие изменили после нашего действия — «Встречу уже изменили, отменить всё равно?».

### US-62. Несколько действий в одном сообщении (P2)
> «Перенеси встречу с Петей на пятницу и поставь созвон с Машей на её место»

- Одна карточка со списком действий; журнал отмены хранит список обратных операций.

### US-64. Подсказки о функциях (P2; учёт — с MVP)
Как пользователь, я хочу узнавать о возможностях бота, которыми ещё не пользовался.

- С MVP бот хранит по пользователю, какие функции он **уже успешно использовал** (интенты, повторения, алиасы, дайджесты, отмену и т.п.) и когда впервые.
- Позже (P2): ненавязчивые подсказки о неиспользованных функциях — например, в конце утреннего дайджеста, не чаще `[допущение: раза в неделю]`, с возможностью отключить в `/settings`.
- Подсказки контекстные, где можно: после третьей вручную созданной еженедельной встречи — «можно сказать "каждый понедельник"».
- Те же данные пригодятся для продуктовой аналитики и для объяснения ценности при окончании триала (ADR-0004).

### US-63. Общий календарь: два пользователя
- События, созданные супругой в общем календаре, видны обоим как обычные события.
- Конфликт правок решается через `etag` (см. правила эпика 5 и US-61).
- Пересечения при создании не учитывают события другого пользователя в общем календаре, если создаём не в общий `[допущение]`.

## Эпик 7b. Событие из чужого контента (R1)

Самый частый реальный повод добавить событие — не «вспомнил», а **сообщение от кого-то**: договорённость в чате, приглашение, запись к врачу, билет. Пользователь пересылает это боту, бот предлагает событие.

Общие правила для US-65…US-67:
- **Чужой контент никогда не исполняется как команда.** Пересланное сообщение, скриншот, файл — это *материал*, из которого бот извлекает кандидатов в события. Даже если там написано «удали все встречи».
- **Всегда карточка-подтверждение**, в любом режиме (US-05): текст писал не пользователь.
- Карточка показывает, **откуда** взяты данные: короткая цитата исходного фрагмента рядом с каждым полем, которое из неё извлечено.
- Считается как одно AI-действие (лимиты — ADR-0004).
- Бот **ничего не отправляет** автору исходного сообщения и не создаёт приглашений.

### US-65. Пересланное сообщение → событие
> Пересылает от жены: «Завтра в 7 у Маши родительское собрание, школа 41»
> Пересылает от клиники: «Вы записаны к стоматологу 14.10 в 9:30, ул. Ленина 5, каб. 12»

**Что считается пересланным**
- Сообщение с `forward_origin` (текст, голосовое, фото с подписью, документ).
- Несколько сообщений, пересланных разом (кусок переписки), склеиваются в один контекст: группа по `media_group_id` или пачка, пришедшая в пределах `[допущение: 2 сек]`.
- Если пользователь переслал с комментарием, Telegram присылает комментарий отдельным сообщением. Комментарий — это **инструкция пользователя** к пересланному («в общий календарь», «напомни за день», «это перенос встречи с Петей»). Он склеивается с пачкой по тому же окну.

**AC**
- Относительные даты («завтра», «в пятницу») считаются **от даты исходного сообщения** (`forward_origin.date`), а не от момента пересылки. Если дата исходного сообщения скрыта или пересылка старше `[допущение: 7 дней]` — дата помечается `ambiguous` и уточняется кнопками.
- Пересланное голосовое сначала распознаётся (STT), дальше — как текст.
- Найдено:
  - **0 событий** → «Не нашёл в сообщении даты и времени» + кнопка «Создать вручную» (бот спрашивает дату);
  - **1 событие** → карточка «Создать событие?» с полями и цитатами;
  - **2–5 событий** (например, расписание кружков) → список с переключателями, кнопка «Создать выбранные»;
  - **>5** → «Слишком много, перешлите частями» `[допущение]`.
- Название генерируется из смысла («Родительское собрание — Маша»), а не копирует сообщение целиком. Его можно поправить кнопкой «Изменить».
- В описание события пишется: «Создано из пересланного сообщения» + короткая цитата (до ~300 символов). Имя автора — `[вопрос]`.
- Если в календаре уже есть событие в это время с похожим названием → «Похоже, это уже есть: …» и кнопки «Всё равно создать» / «Не надо».
- Если сообщение похоже на **изменение** («переносим на 8», «отменяется») — бот предлагает найти подходящее событие и показать карточку «Было → Стало». Без найденного события — ничего не делает. `[допущение: в R1 только предложение, автоматический поиск — по комментарию пользователя]`
- Журнал (US-13) хранит **только извлечённые поля и результат**, а не полный текст чужого сообщения.

### US-66. Скриншот / фото → событие
> Скриншот переписки, фото афиши, скриншот письма с бронью, фото расписания на двери кабинета.

**AC**
- Фото без подписи → извлечение событий vision-моделью или OCR + LLM (выбор провайдера — техническое решение R1).
- Фото с подписью → подпись = инструкция пользователя (как комментарий в US-65).
- Дальше те же правила, что в US-65: 0 / 1 / несколько событий, цитаты (фрагмент распознанного текста), дубликаты, всегда подтверждение.
- Дата «завтра» на скриншоте считается от **текущего** момента, но всегда помечается `ambiguous`: дату скриншота мы не знаем.
- Изображения не хранятся после обработки.

### US-67. Файл приглашения `.ics` (R1)
- Пересланный или загруженный `.ics` разбирается **без LLM** (детерминированно): название, время, место, повторение.
- Карточка «Добавить в календарь?»; если событие с тем же `UID` уже есть — «Уже в календаре».



Настраиваются в `/settings` → «Уведомления» или голосом. Время — в текущем поясе пользователя (US-07). Источник — все подключённые календари, фильтры как в US-20.

### US-70. Дайджесты
| Дайджест | Когда (по умолчанию) | Содержимое | По умолчанию |
|---|---|---|---|
| **Сегодня** | 08:00 | события на сегодня | вкл |
| **Завтра** | 21:00 | события на завтра | выкл |
| **Неделя** | вс 20:00 **или** пн 08:00 (выбор) | события на предстоящую неделю (пн–вс) по дням | выкл |

**AC**
- Пустой период → «Завтра встреч нет».
- Формат как в US-20.
- Отклонение от времени отправки ≤ 1 мин.

### US-71. Напоминания о встречах в Telegram
> «Напоминай мне в телеграме за 10 минут до встреч»

**AC**
- Независимы от напоминаний Google: глобально «за N минут» `[допущение: выкл, N=10]`.
- Точность: приходит не раньше чем за N+1 и не позже чем за N−1 минуту.
- События на весь день и отклонённые не напоминаются.
- Сообщение: название, время, место/ссылка на звонок.
- Событие перенесли/удалили → напоминание по актуальному времени или не приходит.

## Эпик 9. Семейный диспетчер (R1, ядро продукта)

> «Перешлите сообщение — бот занесёт его в общий календарь, напомнит, кому нужно, и проследит, что дело взяли».

Главная боль — «передать дело другому взрослому и перестать держать его в голове» (см. [research/pivot-options.md](research/pivot-options.md)). Напоминает **бот, а не партнёр**. Схема данных закладывается с R0 (ADR-0003), функциональность — с R1.

Общие правила для US-90…US-95:
- Тон напоминаний **всегда нейтральный**: «Напоминание: забрать Машу в 17:00», без «жена просила». Автор поручения виден в деталях, но не в заголовке.
- Никакого «табло» — бот не считает, кто сколько сделал.
- Поручение ≠ событие: поручение может быть привязано к событию в календаре, а может существовать само по себе («купить подарок до пятницы»).

### US-90. Участник без Google
Как член семьи, который не ведёт календарь, я хочу получать свои дела и расписание в Telegram, не подключая Google.

- Взрослый с OAuth приглашает в дом по одноразовой ссылке `t.me/<bot>?start=home_<code>`.
- Участник: нажимает ссылку → `/start` → «Вы в доме "Бобылевы". Будете получать напоминания и расписание семьи». OAuth не требуется.
- Участник может: получать поручения и напоминания, отвечать кнопками, спрашивать «что у нас завтра?» (по общим календарям дома — через аккаунт владельца календаря), в любой момент подключить свой Google.
- Участник **может создавать и менять события в общих календарях дома** — запись идёт через аккаунт владельца календаря. Событие можно сразу назначить на взрослого или ребёнка («для кого» / «ответственный», US-92). В карточке видно, кто создал.
- Свой личный календарь у участника без Google, естественно, недоступен.
- Выйти из дома — `/leave`; владелец может удалить участника.

### US-91. Поручение и напоминание другому
> «Напомни мужу забрать Машу из школы в 17», «Пусть Аня завтра купит торт», «Кто-то должен отвезти Ваню на плавание в субботу»

**Поток**
1. Автор говорит голосом/текстом → карточка: что, кому, когда, напоминания, связать ли с событием в календаре.
2. После подтверждения исполнитель получает сообщение: «Забрать Машу из школы — сегодня в 17:00» + **Беру** / **Не могу** (+ «Предложить другое время» — позже).
3. «Беру» → автор получает «Дима взял». «Не могу» → автор получает «Дима не сможет» + кнопки «Сделаю сам» / «Предложить другому».
4. Напоминания исполнителю — по умолчанию `[допущение: за 1 день (если поручение на завтра и позже) и за 1 час]`.
5. **Эскалация:** если исполнитель не ответил `[допущение: за 2 часа до срока]` — автору: «Дима ещё не подтвердил»; опционально — сообщение в семейный чат (US-94).
6. «Кто-то должен …» (без исполнителя) → предложение всем взрослым дома, первый «Беру» забирает.

**AC**
- Исполнитель — участник дома (с Google или без).
- Имя исполнителя сопоставляется по алиасам участников дома («муж», «Дима», «папа») — настраивается при приглашении.
- Если поручение связано с событием — у события появляется ответственный (US-92); перенос события сдвигает напоминания поручения.
- Исполнитель может отметить «Сделано»; после срока без отметки — статус «истекло», без упрёков.
- Отмена поручения автором → исполнитель получает «Отменено».

### US-92. Ответственный и «для кого»
> «Стоматолог Вани в четверг в 16, отводит папа», «Плавание Маши по субботам в 10»

- У события можно указать **ответственного** (взрослый/участник) и **для кого** (ребёнок — `Dependent`, без аккаунта).
- Хранится у нас (`EventMeta`), видно всем участникам дома в списках, дайджестах и брифингах: «10:00 Плавание (Маша) — отводит Дима».
- Для повторяющихся событий ответственный может быть задан для серии или для конкретного вхождения.

### US-93. Дайджест для участников дома
Отдельного «брифинга» нет — это обычный дайджест (US-70) с семейными данными:
- у событий видно «для кого» и «отводит / ответственный»;
- поручения участнику на этот период;
- блок «Подготовить» (что принести/сдать), если есть;
- участник без Google тоже получает дайджест — по общим календарям дома.
Время и состав настраиваются так же, как в US-70.

### US-94. Бот в семейном групповом чате
- Бота можно добавить в семейный чат; чат привязывается к дому.
- В чате бот: отвечает на «что у нас в выходные?», показывает карточки поручений (кнопки видны всем — «Беру» может нажать любой взрослый), публикует эскалации, по желанию — общий утренний дайджест.
- Команды в группе — только по упоминанию `@bot` или reply боту (privacy mode); бот не читает остальную переписку.
- Создание/изменение событий из группы — только участниками дома с Google, с подтверждением.

### US-95. Inline-карточка «📅 Добавить себе»
> В любом чате: `@bot завтра 19:00 футбол`

- Telegram inline-режим: бот предлагает карточку события, автор отправляет её в чат.
