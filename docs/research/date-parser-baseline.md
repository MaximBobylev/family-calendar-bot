### Пробелы chrono в русском

**Не разбирает (`unparseable`):** «в полтретьего», «в половине третьего», «без пятнадцати три», «без четверти шесть», «в пятнадцать тридцать», «двадцать третьего», «третьего», «23-го», «на 14-е», «14.10», «5.11.26», «в выходные», «днём», «29 февраля».

**Опаснее — уверенно возвращает НЕПРАВИЛЬНЫЙ ответ:**

| Фраза (сейчас ср 07.10 10:00) | chrono | Должно быть |
|---|---|---|
| «в пять минут восьмого» | 07.10 **10:05** | 07:05 / 19:05 |
| «через полтора часа» | **11:00** | 11:30 |
| «с часу до двух» | **11:00** | 13:00–14:00 |
| «в среду 14-го» | 07.10 **14:00** | 14.10 |
| «в 12 ночи» | **12:00** (полдень) | 00:00 |
| «после дождичка в четверг» | **чт 08.10** | не разобрано |
| «двадцать пятого октября в десять утра» | 25.10 **без времени** | 25.10 10:00 |
| «7 октября в 12» (сегодня) | **2027**-10-07 | 2026-10-07 |

Принцип ADR-0005: «если парсер не смог — уточняем, а не догадываемся». С chrono этого не обеспечить: молча-неверный результат неотличим от верного.

## Варианты

- **A. chrono для английского, свой парсер для русского.** Два механизма, при переезде на Go — другая библиотека для английского с другим поведением.
- **B. Свой парсер для обоих языков, chrono не используем.** Узкий домен (короткий фрагмент, вырезанный LLM; ограниченный словарь), корпус — готовая спецификация. Неизвестное слово → `unparseable`, без догадок. Одна грамматика → одинаковое поведение в TS и будущем Go.
- **C. chrono + патчи через его механизм расширения (свои парсеры/рефайнеры).** Борьба с внутренностями библиотеки, неверные ответы базовых парсеров всё равно надо перехватывать.

## Решение

Вариант **B** — свой парсер (ADR-0005 п.8). Результат: **231 / 231** на корпусе, включая 33 разговорных кейса, добавленных после первой версии (`11-colloquial.yaml`) для проверки на переобучение; незнакомые формулировки («на днях», «после работы», «до пятницы») возвращают `unparseable`.
