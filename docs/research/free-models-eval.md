# Бесплатные модели OpenRouter: текст, голос, картинки (2026-10-08)

Вопрос: годится ли какая-то из четырёх новых **бесплатных** моделей OpenRouter в цепочку — LLM для текста (основная или запасная), переслушивание голосового (`VOICE_CHAIN`), фото → событие (US-66).

Модели: `dots-studio/dots-3-note-preview:free`, `thinkingmachines/inkling:free`, `thinkingmachines/inkling-small:free`, `nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free`.

## Итог

- **Inkling и Inkling Small — недоступны.** На любой запрос (текст и картинка) ответ **403 «only available on agentic harnesses»**. Бесплатные варианты открыты только для приложений из списка openrouter.ai/apps, а не для нашего ключа. Это не сбой, который пройдёт сам, поэтому замер не проводили.
- **Dots3-Note — точный, но медленный.**
  - Текст: R1 — **95,5 %** всех полей; на 107 фразах, где был ответ, — 98,1 %. Основной набор — **89,2 %**: 11 из 148 упали по таймауту 15 с после трёх повторов, на ответивших 96,4 %.
  - Задержка — **p50 5–7 с, p95 12–14 с**: в 5–10 раз медленнее Nemotron Super и DeepSeek flash.
  - Картинки: **лучший результат из всех**. Событие 12/12, название 10/10, место 9/9, дата — 8/10 (два промаха — ошибки нашего парсера, не модели; исправлены, tech-debt #25). Но p50 16 с, p95 26 с.
  - Рассуждение не выключается: `reasoning: {enabled: false}` вместе с `tool_choice: "required"` даёт 400 у провайдера (AtlasCloud). С `required` и включённым рассуждением аргументы приходят битые (`{"assignee": ": "}`). Работает только `tool_choice: "auto"` с рассуждением по умолчанию.
- **Nemotron 3 Nano Omni — сырой и перегруженный.**
  - Текст (рассуждение выключается): на ответивших фразах около **80 %** всех полей, p50 1,4–1,6 с, p95 2,9–3,4 с. Типичная ошибка — дробит одну команду на два вызова инструмента.
  - Провайдер (Nvidia) постоянно перегружен. Большинство запросов получают **HTTP 200 с телом `{"error": … ResourceExhausted … (16/16)}`** — до 74 из 110 в первом прогоне.
  - **Голос не работает.** `input_audio` в OGG — 400 (`untagged enum ChatCompletionRequestUserMessageContent`). WAV и MP3 провайдер принимает, но аудио до модели не доходит: 23 входных токена, ответ «Mm-hmm.», на чистой речи — `no_speech`.
  - Картинки: на 7 из 12 ответов всё верно по событию, дата верна в 5 из 6. Остальные 5 — `ResourceExhausted` или таймаут 25 с.
- **Рекомендация: ни одну не ставить в цепочку.** Подробности — в разделе «Рекомендация».

Метод: [llm-intents-eval.md](llm-intents-eval.md). Промпт — вариант E, после модели — детерминированные поправки как в проде. Параметры: `--concurrency 1 --delay-ms 2500`, `--live`. Набор R1 — `testdata/nlu/intents-r1.yaml` (110 фраз), основной — `testdata/nlu/intents.yaml` (148).

Основной набор прогнали только на Dots: порог был ≥ 95 % на R1. Inkling в замер не попали (403).

**Ошибки Dots** (кроме таймаутов):
- «Созвон с командой» (без даты) → `unsupported`;
- «В пятницу у меня выходной» → `unsupported`;
- «Давай созвон с Петей лучше в четверг» → `create` вместо `modify`;
- «Добавь Ване в календарь тренировку» — календарь «Иван» не найден;
- R1: «Попроси Аньку купить хлеб по дороге домой» — «по дороге домой» ушло в срок;
- однажды кириллица в аргументах заменилась латиницей: «забрать **mashu** из садика».

**Ошибки Nemotron Nano:**
- дробит одну команду на два вызова: «Попроси жену в воскресенье в 12 приготовить обед» → `assign_task{task}` + `assign_task{when}` → `multiple`; так же — «Плавание Маши по субботам в 10» и «Папа отведёт Ваню к врачу в пятницу в 10» (`assign_task` + `create_event`);
- задачи «вынести мусор **из дома**», «**помнить** про врача».

С включённым рассуждением ответ занимает около 9 с, и модель всё так же дробит команду. Поэтому с рассуждением R1 целиком не гоняли.

**Находка для прода.** OpenRouter отвечает **HTTP 200 с `{"error": {"code": 502, …}}` без `choices`**. `callTools` (`src/nlu/llm.ts`) и `viaOpenAiAudio` (`src/voice/understand.ts`) принимают такой ответ за «модель не вызвала инструмент». Последствия:
- в тексте ответ становится `unsupported` («не понял»), и запасная модель цепочки не вызывается;
- в голосе он становится `no_speech`.

В замере (`scripts/eval-*.ts`) такой ответ считается ошибкой провайдера. В `src/` правку не вносили — это кандидат в `docs/tech-debt.md`: проверять `json.error` и бросать `LlmHttpError`, тогда цепочка перейдёт к следующему провайдеру.

Для замера в `scripts/eval-voice.ts` добавлен конвейер **C**: прод-путь `understandVoiceChain` с `kind: "openai-audio"`, `input_audio` в формате `ogg`, те же `VOICE_TOOLS` и правила. Поля провайдера (reasoning off) вклеиваются в запрос.

DeepSeek flash в этой строке — одна проверочная картинка. Полный прогон на 12 картинках не делали: автоматическая проверка прав остановила его как трату денег на платную модель, на которую не было разрешения владельца. Если нужно — запустить с явного разрешения: `--models ds:deepseek-flash`, ≈ 12 вызовов, доли цента.

**Промахи Dots и обоих Nemotron на картинках — это ошибки нашего парсера дат.** Модель текст прочитала верно, и на эталонном тексте (`oracle`) те же промахи:
- **03, чат**: «…встретиться / на выходных?» … «В субботу в 12:30». `foreignDateSpans` склеивает «на выходных В субботу в 12:30» и получает **только дату** 10.10, без времени. Dots в своём `start` вернул «в субботу в 12:30», и по нему было бы верно.
- **11, афиша на английском**: «Jazz Night / Saturday, Oct 24 / Doors 7:30 pm». Парсер считает «**Night**» датой «сегодня» и даёт 2026-10-08. Когда Nemotron вернул текст одной строкой, вышло 24.10 без времени.

Оба случая исправлены (tech-debt #25, 2026-10-08): склейка дат в `foreignDateSpans` принимается, только если даёт время, а «В субботу в 12:30» уточняет «на выходных»; «night» без дня — не дата. Пересчёт по сохранённым ответам (`--report`, без вызовов): дата 10/10 у oracle, DeepSeek flash и Gemini.

## Рекомендация

1. **Текст: не брать ни одну.**
   - Dots по качеству на уровне Nemotron Super и DeepSeek: R1 98 % на ответивших. Но p95 ≈ 13 с, а 7 % запросов основного набора не уложились в наш таймаут 15 с. Для команды голосом это неприемлемо даже как запасная модель: запасная включается, когда основная уже потратила время. Модель — превью со сроком до 31.12.2026.
   - Nemotron Nano хуже Nemotron Super (80 % против 97 %), и у неё нет живого провайдера.
   - Текущая цепочка (Nemotron Super free → …, на запуске — DeepSeek flash первым) остаётся.
2. **Голос: не брать.** Ни один бесплатный аудиокандидат через наш ключ не работает: Inkling — 403, у Nemotron Nano аудио не доходит до модели. Переслушивание остаётся на Gemini 3.5 Flash-Lite.
3. **Фото → событие: Dots — кандидат «на будущее», не сейчас.**
   - По качеству лучший из проверенных на этом наборе: все поля верны, кроме двух промахов нашего парсера.
   - 16–26 с на картинку — на грани таймаута 25 с, и цепочка `vision` сейчас умеет только Gemini (`kind: "gemini"`).
   - Если Gemini из Cloudflare начнёт стабильно сбоить, Dots можно добавить запасным: нужен OpenAI-совместимый путь в `src/vision/understand.ts` (`image_url`, `tool_choice: auto`) и таймаут около 40 с с сообщением «читаю картинку…».
   - Перед этим стоит сравнить с DeepSeek flash (платный, ≈ 3 с) на этих же 12 картинках.
4. **Исправить у себя**, независимо от выбора модели:
   - ответ OpenRouter 200 с `error` считать сбоем провайдера в `callTools` и `viaOpenAiAudio`, чтобы цепочка шла дальше;
   - ✅ два промаха парсера дат на картинках: «на выходных … в субботу в 12:30» и «Jazz Night» (tech-debt #25).

## Как повторить

```sh
# текст (dots: рассуждение не выключается, tool_choice только auto)
docker compose run --rm --entrypoint npx deploy tsx scripts/eval-intents.ts --set testdata/nlu/intents-r1.yaml --variants E \
  --models or:nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free --concurrency 1 --delay-ms 2500 --live reports/free-eval/r1.log --out reports/free-eval/r1.json --failures
docker compose run --rm -e OR_EXTRA='{"tool_choice":"auto"}' -e OR_MAX_TOKENS=2000 --entrypoint npx deploy tsx scripts/eval-intents.ts … --models or:dots-studio/dots-3-note-preview:free
# голос: конвейер C на подвыборке
docker compose run --rm --entrypoint npx deploy tsx scripts/eval-voice.ts --only C --files r01-dmitry-clean.ogg,… --results results-free.jsonl
# картинки (oracle — без вызовов, можно в сервисе test)
scripts/image-synth.sh   # на хосте, только при правке набора
docker compose run --rm --entrypoint npx test tsx scripts/eval-images.ts --models oracle --out reports/free-eval/oracle.jsonl
docker compose run --rm -e OR_EXTRA='{"tool_choice":"auto"}' -e OR_MAX_TOKENS=4000 -e IMG_TIMEOUT_MS=60000 --entrypoint npx deploy tsx scripts/eval-images.ts \
  --models or:dots-studio/dots-3-note-preview:free --delay-ms 3000 --out reports/free-eval/images.jsonl
docker compose run --rm --entrypoint npx test tsx scripts/eval-images.ts --report --out reports/free-eval/images.jsonl
```

Новое в скриптах:
- `eval-intents.ts`: `--max-fail-streak` (после 5 сбоев подряд модель пропускается), `OR_EXTRA` и `OR_MAX_TOKENS`; ответ 200 с `error` считается HTTP-ошибкой и повторяется.
- `eval-voice.ts`: конвейер C (`VOICE_OR_MODEL`, `VOICE_OR_EXTRA`) и `--files`.
- `eval-images.ts`: модели `or:`, `ds:`, `gg:` и `oracle`.
